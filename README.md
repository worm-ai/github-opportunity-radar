# 机会捕手

机会捕手把自然语言需求转成可核查的开源实现研究：搜索 GitHub、保存原文证据、比较直接采用/单项目改造/组合方案，再给出下一项最小验证。它是研究和选型助手，不是自动生成完整产品的代码代理。

## 先运行起来

环境要求：Node.js 24 或更高版本、Corepack、Windows/macOS/Linux 任一开发环境。

```powershell
corepack pnpm install
Copy-Item .env.example .env
corepack pnpm build
corepack pnpm start
```

打开 <http://127.0.0.1:4317>，然后进入“需求研究”。如果要使用 iii Engine，把 `.env` 中的 `III_URL` 配好并先运行 `corepack pnpm engine:start`；没有 Engine 时可使用本地执行器，但模型和 GitHub 凭证仍取决于本地配置。

开发模式：

```powershell
corepack pnpm dev
```

首次使用 GitHub 实时研究前，在 `.env` 填入只读公开仓库权限的 `GITHUB_TOKEN`。如果企业网络使用 HTTPS 检查代理，只能配置管理员确认过的 PEM CA bundle 到 `RADAR_GITHUB_CA_FILE`；不能关闭 TLS，也不能使用失败连接中保存的叶证书。

## 推荐使用路径

1. 在 `/research` 描述目标、必须能力、运行条件和成功标准。社会模拟是验收案例，不是产品本身要交付的游戏引擎。
2. 等待系统完成需求拆解、GitHub 搜索、有限资料采集、候选比较和反方审查。每个结论都应能回到保存的原文引用。
3. 从结果页的“当前行动摘要”开始，只选择一个最小下一步：查看源码、记录判断，或启动已登记的受控实测。
4. 如果要判断是否真的省时，在“记录本次任务对照”中记录同一任务的人工基线和使用后方法。表单内置本地计时器，可分别填入基线和使用后耗时；没有计时就保留“未记录”。保存前仍需人工检查可比性、是否完成和误留/漏选。
5. 下载研究 JSON 或离线交接简报，把需求、证据、判断、实验边界和下一步一起交给其他人复核。

如果还没有研究判断，也可以在 `/research` 的“独立任务对照”中直接记录一次真实任务；它不要求候选或引文，但只描述这一条任务，不能推出普遍省时。

网络不可用时，需求页可以主动查看“本地缓存线索”。缓存结果带观察时间和有限摘录，只是历史线索，不是实时 GitHub 状态、推荐、运行证明或组合兼容证明。

网络不可用时，需求页还会把缓存命中整理成“离线证据短名单”：优先显示同时有项目描述和 README 摘录的项目，并给出下一项人工核验动作。它只是阅读顺序，不是推荐；固定版本、依赖、启动和运行结果仍需人工确认。

提交遇到 GitHub 预检失败时，未提交需求会在此浏览器本地保留，刷新 `/research` 可恢复；它不会创建服务端任务或伪造搜索结果，也可以随时清除。

## 当前已经验证的能力

- 需求研究链路：拆解、有限搜索、资料采集、单项目/改造/组合比较、引用校验、反方审查、失败恢复和离线导出。
- 受控实验交接：登记的实验可以从产品入口启动，读取固定提交、日志、产物哈希和失败边界。
- `agent-world` 本地桥接：固定提交上的三角色规则循环、检查点恢复、玩家事件可见性和事务失败回滚已有归档证据；这些证据不等于上游原版、外部 LLM 社会智能或完整游戏。
- 任务价值记录：判断、任务对照、耗时、误留/漏选和修订关系会和需求材料一起保存；一次记录只描述一次使用，不推出普遍收益。
- 独立任务对照：无需先保存研究判断即可持久化同一任务的基线、使用后方法、计时和导出结果。

## 当前明确的限制

- 本机到 GitHub 的实时 HTTPS 可能因证书链或网络认证失败而在预检阶段停止。失败时产品必须停止搜索，不能伪造“没有候选”。
- 尚未对任意候选执行通用依赖安装、启动、接口探测和多项目状态衔接；“组合方案”默认仍是待验证假设。
- 没有独立外部用户的前后计时、判断变化或付费意愿证据。助手自用和技术测试会单独标注。
- 受控社会模拟实验没有覆盖完整图形界面、长期负载、所有进程中断边界或外部 LLM 行为。
