# 历史候选与采集、分析阶段可见性复核

2026-10-22。修复了两种会削弱研究判断的界面语义：一轮分析完成或失败时，最新批次的信息可能被仍在列表中的其他批次机会遮住；同范围分析没有再次提出旧假设时，旧候选虽仍留在 SQLite，却不能从用户工作台复查。这项修改保留“当前列表代表当前分析”的含义，同时让旧假设可见、有状态、有出处。

## 第一性原理与对抗性审查

一个候选被移出最新列表，只能证明模型在一次有界、特定输入的分析里没有再次保留它。它不能证明原假设被原文反证、上游已修复、替代方案更好、用户没有这个问题或不愿付费。相反，直接把所有旧候选堆回当前列表，又会混淆批次结果并增加筛选成本。故保留当前列表和机会计数的原语义，另加明确的“历史候选”查询和入口；收藏、验证中项目仍进入当前列表，显式忽略继续排除。历史项目可进入详情、复查研究判断并选择收藏或验证，所有这些动作仍不产生市场验证。

最新分析概要始终显示其时间、研究范围、深读项目、保留/淘汰数和问题，即使别的研究范围仍有当前候选。失败状态不会被存活候选掩盖。采集记录先到达持久化终态，模型分析再单独占用工作槽；界面允许阅读刚采集的项目，却在分析仍运行时禁止并发扫描。

对抗性边界：模型、抽样的 GitHub Issues 和模型反方不是独立市场证据。历史“移出时间”字段此前已存在，但过去未记录一致批次的真实发生时刻，所以本次不回填时间，只把日期标为历史状态时间；当前数据库十条候选的时间戳来自旧流程，可能晚于实际移出时刻。被忽略候选不会在历史入口中复活；用户可以从详情看到被忽略前的材料，但不能一键撤销忽略。若只反复分析相同方向，历史会逐渐积累，产品还需要按假设身份比较用户研究状态，而不能把历史数量当成果。

## 实现与兼容

- `GET /api/v1/opportunities` 保持当前工作台和 dashboard 计数不变；新增 `?view=history`，只查询被同范围后续分析移出且仍为 `candidate` 的完整记录。
- 更新 superseded 时间时只赋给尚未移出的记录，不再每次成功分析都覆盖时间。冲突更新沿用机会组合 key，避免重提时生成重复身份。
- 详情和 Markdown 导出展示“历史候选”，说明移出列表并非反证；用户收藏后项目回到当前列表，机会状态保持 `unvalidated`。
- Promise 流程恢复为单一返回链：collection 终态已先持久化，然后直接 await/传播第二个 Engine call 的结果。原分拆 `{ ids, analysis }` 容易让调用方错误解构或产生未处理拒绝，分开的耐久状态不要求分拆同一 Promise。

- 迁移兼容：本轮没有 schema 变更。存储单元测试验证不同研究范围各自刷新、历史项目重启后可读、同候选 ID 被更新、收藏或验证状态保留、显式忽略不复活、历史项目不计入当前机会数量，且 `marketStatus` 不自动变化。
- 定向测试：存储、扫描管线和研究简报共 28 项测试通过；collection 成功结果在 analysis timeout 后保持不变。

## 真实价值的下一步

当前工作改善的是系统可信度和研究资料可回看性，不是市场价值验证。工作区当前仍只有 DOCX 一条可见机会；它有一个作者的公开 Issue 和合成 DOCX 的固定版本解析实验，不含真实使用者、使用频率、时间/返工成本或支付信号。2026-10-22 的只读复核确认 #191 仍开放、无评论，作者关联为 `NONE`；同仓库 #202、#203 也是同一作者（`serjdrej`）的文档审阅层问题，因此增加了问题形态的线索，却没有增加独立客户样本。当前主分支的 `content.rs` 与关系解析 Blob 中未出现批注关键词；这不能证明所有发行物、绑定层或未来版本都没有修复。GitHub issue 搜索查询 `repo:firecrawl/anydoc comments is:pull-request` 匹配 35 条仓库内 PR，其中标题/正文明确提及 `comments.xml`、`commentRange` 或 #191 的结果为零；关键词搜索可能遗漏以其他说法实现或未索引的代码。原始快照见 `.data/research/2026-10-22-docx-review-layer.json`，复跑命令为 `node scripts/research-docx-review-layer.mjs`。

最高信息价值的后续是核实可公开、已获授权的真实使用工作流和匿名化样本，比较 AnyDoc 单独转换、GenOffice 的 standalone 转换、结构化批注读取及人工流程的输出与成本。如果手头没有授权真实文档，停止扩大适配器，继续核查该 Issue 的后继 PR/发布，并从当前 Issue 语境寻找独立使用者或维护方证据；不向外发消息、不读取私有数据，也不将公开 Issue 数量包装成市场验证。只在真实工作流重复受损、已有免费工具不足、额外组合显著降低成本时才实现窄适配器，继续保持机会 `marketStatus=unvalidated`，直到记录真实的外部验证。
