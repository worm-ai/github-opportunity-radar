## 原则与实验边界

组合的价值必须来自仍未满足的任务。若现有工具已经做了拆分和退款识别，就不能通过重新描述功能生成商机；若有缺口，也应先比较局部修改，而不是默认新产品更好。

固定来源为 [rr4444/actual-ecommerce-noter](https://github.com/rr4444/actual-ecommerce-noter/tree/52aa8ada3fbd602b80df52cd10fe95206488bcdb)，提交 `52aa8ada3fbd602b80df52cd10fe95206488bcdb`。CLI Blob `582b07eee3e183ae7834899b876d1b7754fa9e92`；准备和执行时核对原文件哈希，没有修改上游解析、匹配或输出逻辑。源码已包含精确匹配、多订单合并、礼品卡分摊、退款商品回溯与结构拆分路径；本次没有覆盖全部功能。

[实验方法与脚本](../../experiments/actual-ecommerce-noter/README.md)。独立 Windows x64 Python 3.12.10 环境，真实 requests 2.32.5；精确 wheel 版本及 SHA-256 记录于产物。Python ZIP 按首次下载的固定观测哈希核对，未另验发布者签名。依赖准备经历 PyPI 超时，检查发现部分 DNS 地址不可达；下载器只在解析所得地址间尝试，保留主机名、SNI 和证书校验，已下载依赖可校验缓存后复用。

运行真实未修改的 CLI，输入全部是明确标记的合成 CSV；Actual HTTP API 由 127.0.0.1 随机端口临时服务器替代，仅提供读取账户和交易。进程不收到本项目密钥或真实预算环境；每次 API 请求都有记录，非 GET 拒绝。固定参数为 Amazon 格式、金额容差 0、日期容差 3 天、JSON dry-run。

因此能验证当前 CLI 的读取、解析、匹配及预览路径；不能证明真实 Actual/actual-http-api 的版本兼容、真实记账成功、官方 CSV 格式覆盖、默认容差、多币种或现实错误率。

## 九次实测

| 合成任务 | 原始输出观测 | 对判断的影响 |
| --- | --- | --- |
| 单个 50 英镑订单、一笔 -50 流水 | 1 个潜在匹配，正确订单 ID | 正向对照通过。 |
| 一订单内 20/30 两商品、一笔 -50 流水 | 1 个匹配，2 个子交易预览 | 已有商品级拆分能力，不能再当空白。 |
| 两个 20/30 订单、一笔 -50 合并扣款 | 1 个匹配，两个订单 ID，2 个子交易预览 | 已有多订单合并，不能宣称只支持一一匹配。 |
| 一个 50 订单、-20/-30 两次发货扣款，无礼品卡标记 | 0 个匹配，两笔均未返回 | 这一输入上的一对多发货匹配未得到满足。 |
| 两个同日 30 订单、一笔 -30，CSV 正序 | 单个候选 SYN-A | 原始输入不能唯一判定归属。 |
| 上述同一数据仅逆转订单行序 | 单个候选变为 SYN-B | 选择依赖遍历顺序；不能据此确定哪个必错。 |
| 20/30 两商品中退款 20，+20 流水 | 回溯唯一同额商品 | 退款不是完全缺失的能力。 |
| 两个等价 20 商品中退款 20 | 商品字段保留 `Candidates: A / B` 信息 | 已有商品歧义提示，应保留这个反证。 |
| 金额相同但商户为非 Amazon 的负例 | 0 个匹配 | 商户筛选对照通过。 |

九次 CLI 均退出 0、无标准错误，所有账本 API 请求为 GET。单订单及合并场景的金额和商品是合成真值；等额场景刻意缺少可辨识信息，没有给其中一个订单虚构“正确答案”。

源码的 [match_transactions](https://github.com/rr4444/actual-ecommerce-noter/blob/52aa8ada3fbd602b80df52cd10fe95206488bcdb/actual-ecommerce-noter#L643)依次消费订单，合并路径尝试多个订单之和，而单订单部分扣款路径要求礼品卡标记。这与实测相符，但不能外推其他格式、版本或真实数据。本次金额容差为 0，未再测试默认 1 英镑容差。

## 对抗审查后的决定

最强反对意见是工具已经要求 dry-run，并将输出称作 potential matches：一个候选随行序变化不等于承诺了确定匹配，也不等于用户实际受损。其退款分支还明确保留 Candidates，不能将工具描述成“完全忽略歧义”。

因此将先前的“继续核查”修订为 **停止另做通用商品分类器**。分批扣款未匹配与等额候选显示是具体边界，当前更适合评估已有项目的局部改进；没有实际任务频率、替代对照或用户选择证据，就不能推出独立复核平台或商业机会。接下来不继续围绕这一案例扩建金融业务或通用执行器，转向其他任务。
