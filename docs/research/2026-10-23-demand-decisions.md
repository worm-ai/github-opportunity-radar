# 需求研究 → 选型判断：助手自用与验收边界

## 为什么补这一环

用户目标是从自然语言需求找到可落地的开源实现路径。已有系统保存研究和人工实验，但用户不能在需求结果页直接留下与这次材料对应的判断。已有研究笔记只能引用当前项目档案，不能正确引用历史源码和后补实验。强行复制实验结论到 README 引用会失真，另建任务系统则重复已有能力。

本次复用研究笔记，增加历史需求关联及两类准确来源。不是自动选中一条路线，也没有自动执行下一实验。PRD v0.28 §4.4.10 记录范围。

## 产品行为

- 需求结果页提供“记录选型判断”直达入口，选择 1～3 个候选，保存继续、等待或停止的理由及下一步。提示填写通过和停止/换路线条件，不替用户填造已通过的验收。
- 来源是指定历史任务实际保存的描述、README、文档、源码，以及关联且产物校验通过的人工实测。服务端校验项目、任务、来源和连续引文；客户端检查不能代替服务端校验。
- 人工实测按 GitHub 名称和地址关联，不能仅靠数字 ID。引用保存具体提交、环境、输入来源及全部限制；多组件实验的全部仓库仍保留，不能把组合结果归给一个组件。
- 同一 SQLite 研究笔记保留幂等性、修订历史和 Markdown 导出，schema 仍为 15。旧模型结果保持原样。已有首页/机会页笔记可返回准确需求及修订入口。
- 执行中的任务不作为冻结来源。旧后端未声明功能时隐藏入口；失败、归档变更或不可用均明确显示，旧引文保留。

## 第一性原理与对抗式结论

判断记录的价值是让下一步可执行、后续可复核；保存成功、更多字段或更多报告不等于需求完成。这次补齐材料到判断的连接，但没有证明路线修复成功、完整游戏可用或独立用户省时。

边界保留在引用中、归档变化会提醒，并不能消除引用片段被误读的风险。下一阶段应检查最小验证是否改变选择；若没有，继续扩展表单和研究报告不能补足真实价值证据。产品仍然是开源实现研究工具，社会模拟游戏是验收样例。
