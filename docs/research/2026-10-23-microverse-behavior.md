# 社会模拟选型：Microverse 行为验证与下一条路线

2026-10-23。承接[固定源码核查](2026-10-23-social-simulation-source-audit.md)及[agent-world 核心实验](2026-10-23-agent-world-behavior.md)。本轮由助手人工执行；机会捕手自动研究尚不下载运行候选。历史模型结论不改写。

结论：当前先走 **agent-world 单项目改造的最小验证**，条件是优先验证社会模拟机制、没有必须使用 Godot 的约束。若必须优先 Godot 画面与玩家操作，则改造 Microverse。两者均未达到完整游戏验收，暂不拼接两套世界状态。这是下一步工作顺序，不是已证实更低工时的最终选型。

## 实际运行与材料

Microverse 固定 `7a061d41ed67825496588e39ca37b0b2b7465fb2`；完整归档按未截断 GitHub 树逐个核对 4,407 份 Git blob。Windows，官方 Godot 4.4.1，下载归档与官方 SHA-512 一致。运行前后所有上游文件未变，只新增诊断驱动；未修补上游脚本、场景或资产。

驱动实例化原版 Office 及 autoload，实际创建 Joe、Jack、Alice、Grace、Monica、Stephen、Tom、Lea 八个角色；在让出帧前停止全部 16 个 AI Timer。两个独立进程共享本次隔离 APPDATA，使用原任务、记忆和存档方法。Alice 的供水任务、Bob 关系与缺水记忆为合成测试输入，非真实玩家数据。未继承宿主游戏配置或 API 密钥。

第一次资源导入在 90 秒预算中断，第二次在 420 秒中断；这两次未完成导入造成的加载错误不计为功能反证。随后导入完成，默认入口短启动与 write/load 均退出 0。导入缓存复用，不作启动性能比较。所有尝试及错误保留，不只归档最后成功退出的进程。

退出 0 不代表应用无错误：仍有五个角色纹理加载错误及多处 UID 回退警告。原版场景内嵌 `CompressedTexture2D.load_path` 指向 `.godot/imported/…ctex`；这些路径在本次导入后仍未找到。headless 状态检查实际到达预定方法，但图形显示、完整菜单、玩家操作及长期运行未验收。

## 实测事实及反证

| 问题 | 原版执行结果 | 判断边界 |
| --- | --- | --- |
| 默认任务是否进入同一份状态 | `_generate_default_tasks` 生成 10 条顶层 metadata.tasks；嵌套 character_data.tasks 仍不存在 | 复现不同状态容器；未模拟自主选择任务 |
| 完成任务是否同步 | 两容器注入互相独立但内容相同的任务，原 `_complete_task` 使嵌套 completed=true，顶层仍为 false；任务 prompt 继续列出同一任务 | 已复现任务读写不一致；prompt 函数本身也未按完成标记过滤，不能只归因于容器 |
| 记忆和关系是否进入输入 | 原 `get_character_status_info` 含缺水记忆和 Bob 的关系强度 7 | 支持 prompt 输入存在；不证明模型理解或行为改变 |
| 任务调整分支是否更改任务 | 原占位重排与紧急任务函数只打印/写记忆，两份任务列表未变 | 只反证已测分支，另有默认后备实现未被否定 |
| 保存是否收集角色 | 实际 controllable_characters 为 8 人，保存用 character 组为空 | 两组不对应；没有为测试偷偷给角色加保存分组 |
| 保存成功是否意味着状态可恢复 | Alice 移到 (333,444) 后 save_game 返回 true，实际 JSON 为 `{}`；新进程 load_game 返回 false，Alice 为 (976,360)，任务/记忆/关系为空 | 反证本次原版存档路径；不能把返回 true 当成成功 |
| 存档断点在哪 | collect_game_data 在 Room 调用不存在的 has_property 报错；单独 collect_character_data(Alice) 在控制器上同样报错并返回空字典 | 即使补齐分组仍有另一处断点；本轮没有修复 |

实际 AI 子节点名为自动生成的 `@Node@…`，而存档器查找名为 `AIAgent` 的节点。原存档器还没有保存本次检验的 metadata 记忆和关系。这些是额外源码/运行线索；未通过逐项修复实验声称每项各自对失败的贡献比例。

驱动阶段未创建 HTTPRequest 节点，AI Timer 已停止；这不是网络抓包结论。没有调用 LLM、没有测试事件后的自主行动，也没有把直接调用“完成任务”包装成智能体自主完成任务。

## 单项目剩余工作比较

从第一性原理看，所需的是可持续的“共享状态 → 个体记忆/目标 → 行动 → 世界及关系变化 → 恢复”闭环。画面、事件文本和字段数量都不能代替它。

| 必要工作 | agent-world（既有受控实测） | Microverse（本轮实测及已读源码） |
| --- | --- | --- |
| 统一状态与可靠恢复 | ORM 已有记忆/关系；需补齐接收者保存、批量连接问题和世界时钟 | 先统一两份任务/记忆状态；修分组、属性检测、AI 节点查找与序列化/恢复 |
| 关系和事件影响行动 | 真实关系更新与广播已有；内置 NPC 对照没有行动差异，需连决策/规则 | 有记忆/关系 prompt 输入；需补齐自动关系变化、共享事件规则、统一任务执行与实际行动对照 |
| 玩家观察与干预 | 完整服务、界面和外部 agent 未验收，需单独评估 | Godot 场景/面板是现有资产；本轮无图形验收且纹理错误待处理 |
| 实现依赖的不确定性 | 已执行核心/ORM，未执行完整 Web/MCP/LLM | 已执行 headless 场景/原方法，未执行完整玩家/LLM 闭环 |

没有两边修复实施工时，不给天数或“成本降低百分比”。agent-world 暂时优先，是因为当前需求优先共享模拟机制、它已有经过执行的世界/关系更新原语；若 Godot 是必要约束，此排序应改变。两个完整状态系统相连反而增加角色 ID、时钟、行动权限、记忆归属和存档同步工作，现阶段没有收益证据。

## 下一项可证伪实验（计划，尚未实现）

只改造 agent-world，先做三角色、一个共享供水资源、最多 30 tick 的规则原型；不接第二个世界框架、不以外部 LLM 掩盖核心状态问题。先修保存，逐项用新进程恢复位置、双方关系、记忆、目标、资源及世界时钟；修复前的反例保留。

然后固定其他输入与随机条件，分别只改变缺水事件、关系或一项相关记忆，比较预先指定的可观测行为（例如是否取水、分享给谁及实际资源消耗）。正对照必须能产生已知动作变化；只有广播、聊天文字或状态标签变化不通过。保存中断后从同一步继续，状态及确定性行为轨迹应一致。

该实验通过只能证明规则闭环，外部 LLM 自主决策和玩家体验另验。若可靠恢复或状态影响行动仍未成立，暂停增加画面和框架组合，围绕实际断点修复或重新比较候选。没有据此声称用户已省时或完整产品已产生独立用户价值。
