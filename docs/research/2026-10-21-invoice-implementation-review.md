# 电子发票方向：先核对后继实现与已有导入工具

2026-10-21。研究结果是停止当前宽泛的“邮件收件＋发票抽取＋校验报告”包装设想，保留重新审视条件。它不否定电子发票市场，也不代表完成客户验证。

## 原始问题与反证

- [Mustang #1320](https://github.com/ZUGFeRD/mustangproject/issues/1320)：作者明确描述常驻进程分析、校验和可视化发票邮件，未捕获异常可能令进程终止。可能只需显式异常捕获，尚不能推出需要新产品、第二组件或存在付费意愿。本轮未运行该 Java 场景。
- [#1311](https://github.com/ZUGFeRD/mustangproject/issues/1311) 仍开放，报告缺少 veraPDF 详细错误；[作者评论](https://github.com/ZUGFeRD/mustangproject/issues/1311#issuecomment-6263008075) 提及 [PR #1314](https://github.com/ZUGFeRD/mustangproject/pull/1314)。真实 API 核实其于 2026-10-19T13:37:27Z 合并，提交为 `d3d51fd01a6a9c1fa4401bc8c08049e3dd0d7020`。文件列表显示修改 `result-pdf.xsl`，增加错误渲染。不能把 open 当作没有实现；也未核查发布版本、复现问题或证明修复有效。
- 正确的 Odoo 现成替代位于 `OCA/edi`，不存在独立的 `OCA/account-invoice-import` 仓库。[18.0 固定提交文档](https://github.com/OCA/edi/blob/08d89ee2fa02dfe9252157b56fc0d2a746106514/account_invoice_import/README.rst) 已描述 POP/IMAP、Factur-X XML、invoice2data 回退、草稿供应商账单/退款和批量导入。需要相应附加模块，不能称为单模块开箱即用；本轮只读取文档，未安装运行。
- [Paperless 电子发票插件](https://github.com/bitbetterde/paperless-ngx-erechnung) README 自述已有 XRechnung、ZUGFeRD/Factur-X 解析、归档与可搜索元数据，依赖 Paperless v3、FOP/JRE，未运行验证。它不证明已有完整校验与异常处置链路，但说明通用解析和归档也不能直接宣称新缺口。

第一性原理：新产品应解决现有做法留下的具体任务，而不是重新组合已有功能。反方审查：异常捕获可能足够，报告已有后继实现，导入已有完整工具自述；尚未观察到这些方案处理不了的实际剩余步骤。因此不强凑商业机会。
