# 组合材料与问题起点复验

2026-10-20。定位以 [PRD](../PRD.md) 为锚点。本轮将“选了几个项目，却不知道研究什么”推进到可核对原文、提出具体工作假设的流程，未增加真实付费分析。

## 从实际障碍出发

一个组合值得研究，首先需要说明它干预哪一步工作、各组件是否有不同作用，以及为什么已有方案或单项目修改不足。仅将两个项目放在一起，不构成商业机会；模型返回零张机会卡片，也不能让用户无法阅读和研究材料。

研究表单现在并排显示所选组件自述、许可证标识、下一步检查、未失效接口文档片段、Blob SHA 和采集时间。项目档案的 Issue 可直接带入表单；选定起点后显示原始片段、作者关系、时间和讨论链接，可以一键起草并编辑问题。材料浏览与起草不提交分析，不调用模型。

## 真实材料对照

使用原库的 [PhotoCraft #7734](https://github.com/storytold/photocraft/issues/7734) 检查流程，问题标题为 `Feature: "Edit in external application" command (send image out, bring result back)`。

采集片段描述外部编辑的往返链路：导出 16-bit TIFF/PNG、启动外部程序、监视返回目录、将结果导入新图层。作者提到插件 sandbox 不允许 imports，可能需要 core command；已有 Python control channel workaround，文件名和 mtime 需防止旧产物误判，部分外部程序还会忽略启动文件参数。原始环境为 Windows 11、PhotoCraft 0.10.0。

这是可定位到具体步骤的障碍，但仍需核对当前讨论、现有 workaround 与是否只需修复 PhotoCraft。样本的作者关系为 NONE，作者登录名未采集，不能称为已确认客户反馈。

浏览器演练同时选择 `phucnguyentvp1/frameweaver`，仅用于验证材料并排呈现与组件更换。它现有自述涉及视频、时间线、语音、字幕与混音，没有证据证明能干预 PhotoCraft 的外部编辑回传。因此这两个项目不构成本轮推荐组合，没有提交真实付费研究，也没有生成机会或市场验证记录。

## 起点合同与反证

- 提交可包含 `focus.originIssue: { projectId, issueNumber }`。起点必须属于所选组件且存在于已采集样本；API 与 provider 在模型调用前检查。
- 候选必须在 `problemEvidence` 引用指定项目的指定 Issue，并通过既有逐字原文校验。省略起点、改引其他问题或编造引文时，在下一次模型审查前淘汰。
- 引文真实只能证明材料存在。方案是否回应障碍、组件是否互补、是否只需单项目修复，仍由反方六项检查与人工复核判断。
- 无效深链不能静默降为无起点研究；页面禁用提交，用户可显式重选。移除起点所属组件时清空起点。
- 不指定起点时可继续研究技术假设，但研究者的问题文本不能作为客户需求证据。
- 起点进入输入 hash、研究范围、持久化和导出；旧无起点数据保持兼容，无 schema 迁移，无自动付费重放。

## 验证结果

105 项测试、包与服务端编译、Web 类型检查和生产构建已通过。新增覆盖不存在/非所选项目起点、遗漏或替换 Issue、伪造引文、精确引用、两角色输入一致、缓存隔离及失败 checkpoint 保存。

`RADAR_TEST_BROWSER=1 node scripts/verify-pipeline.mjs` 已通过。它使用真实 iii Engine、临时数据库和本地 HTTP 模型替身；12 次替身请求覆盖目录选择、提案与反方、失败用量、不同问题/起点隔离、持久化和导出。Edge 在临时库实际提交无起点与有起点研究并执行收藏/验证交互；重复研究命中缓存，没有增加模型请求。替身结果不是 DeepSeek 质量或市场需求证据。

最后一项浏览器断言曾将缓存来源固定为最初模型运行，导致超时。实际缓存查询返回最近成功记录，该记录可为一次复用；核对实现后修正测试，检查来源指向上一次成功复用，完整流程随后通过。未为该断言改动生产缓存规则。

`node scripts/verify-research-materials.mjs` 对真实生产数据只读验证通过：起点深链、原文逐字一致、当前讨论链接、问题起草、移除所属组件清空起点、无效起点阻止提交、390px 无水平溢出。没有写请求或页面错误，生产分析编号未改变。旧浏览器导航、24 个带 Issue 的项目、导出与移动检查也通过。

机器结果与截图位于 `.data/browser/research-materials-verification.json`、`research-materials-desktop.png`、`research-materials-mobile.png`。部署前备份为 `.data/backups/opportunity-radar-2026-10-20T12-32-37-645Z.sqlite`，schema 8，完整性 `ok`。本轮服务仍使用 56 项目、80 条 Issue 样本、94 条观察；未新增真实扫描、付费模型调用或外部验证记录。

## 阶段复盘

入口和约束已让用户能查看问题、对照组件、起草并提交可复核的研究；它没有证明用户更快发现商机。下一阶段应从现有具体问题确认真正缺失的能力，再找到有接口依据的互补组件，允许结论为单项目修改已经足够。应衡量从阅读到继续/停止决策的成本，不以 UI 数量、标签数、模型调用次数或机会卡数量代替价值。
