# agent-world 服务入口验证

2026-10-26 重跑。结论：原版服务入口仍不能直接采用；新增的本地异步桥接在本轮启动器中让注册、动作、tick 和检查点跨进程恢复。两客户端并发动作均完成，注入保存失败时 SQLite 与内存同时回滚，支持继续做单项目服务验证，但尚未完成上游 Daphne 拓扑、长期负载、持续代理或玩家流程验收。

## 执行与来源

固定 `sbenodiz/agent-world@13d62dbdeeca07c7b5bb3b8aa264ca9834b01882`，36 份原版核心及新增 31 份服务文件校验 Git blob，此前改造副本校验 SHA-256。真实 FastMCP Streamable HTTP、官方 MCP 客户端、前端 ASGI、Channels consumer、HTTP 路由、tick loop、Django ORM 和 SQLite 参与。

完成目录：`.data/experiments/agent-world-service/execution-20261026T051406258359Z`。四个子进程正常退出：原版基线加桥接/重载、本地改造加桥接/重载。每种配置记录 8 次顺序 MCP 调用、两客户端并发动作和一次保存失败注入，再读取首个 tick 的 WebSocket、HTTP 和数据库，共 16 次顺序调用。Alice/Bob/Cara/New/Rejected 为合成角色，不调用外部 LLM。

本地启动器以两个 Uvicorn 服务和 tick loop 共用 asyncio loop，仅监听 127.0.0.1:4325/4326；没有验收原版 runworld 的 Daphne 主线程/后台循环拓扑。桥接将同步引擎/ORM 通过 `sync_to_async(thread_sensitive=True)` 调用，注册及每次 tick 后写入本地检查点；这是实验改造，不是上游已有能力。

## 实际对照

| 检查 | 原版基线 + 本地异步桥接 | 本地改造 + 本地异步桥接 |
| --- | --- | --- |
| 初始化、列工具、读 context | 成功 | 成功 |
| remember / emote | 返回 ok，SQLite 与新进程均恢复 | 返回 ok，SQLite、检查点与新进程均恢复 |
| WebSocket / HTTP | 两者一致，显示 emote | 两者一致，显示 emote |
| SQLite / 新进程读取 | Alice 记忆/动作、New 角色恢复；时钟仍回到 06:00 | Alice 记忆/动作、New 角色和 06:15 检查点时钟均恢复 |
| 自动注册 New | 返回 heartbeat，数据库/重载均有 | 返回 heartbeat，数据库/重载均有 |
| 时钟 | 观察 06:15，重载 06:00 | 观察和重载均为 06:15 |
| 无效 key / 动作 | 明确返回相应错误 | 明确返回相应错误 |

旧的未桥接探针日志记录 `Could not save agent Alice: You cannot call this from an async context - use a thread or sync_to_async.`，动作却返回成功；该失败对照仍保存在归档 `logs.json`。本轮桥接额外显式重置 Django 连接，并对注册/动作做同步 ORM 写入。不能用 HTTP 200、MCP 无协议错误或观察端变化作为保存成功证明。

异步桥接把动作与注册放进线程敏感同步边界，并在改造引擎的注册/tick 后写检查点；本轮两客户端并发动作可完成，保存失败时数据库和内存均保持失败前状态。它没有证明重复请求、进程中途终止、长期负载或上游 Daphne 线程拓扑，因此不能称为生产级事务协调已完成。

## 第一性原理与对抗式审查

用户需要可靠的实现选择。一次动作在失败、观察及重启后是否一致，比接通多少协议更有决定意义。本轮证明同步核心不能直接接异步 MCP，同时证明明确的线程敏感桥接边界可以修复本轮顺序服务探针；这不证明生产级实现，也没有证明引入第二个项目能解决问题。

下一项有界验证应覆盖事件等待 → context → 行动 → 观察 → 新进程恢复，并复现真实 Daphne/后台循环拓扑、重复请求和中途退出。不能仅关闭 Django 异步保护，或把所有操作随意丢进线程；队列、回调和共享内存也有循环/线程约束。若需要重做大部分核心，应重新比较候选及改造/组合成本。

本轮额外注入注册和动作保存失败：MCP 返回错误，Rejected 不出现在内存、SQLite 或重载状态中，失败动作也未改变既有内存和数据库。下一次验收仍需复现真实 Daphne/后台循环拓扑并覆盖重复请求和中途退出；本轮只有一次完成执行、每种八次顺序调用、两客户端并发和首个 tick，不证明长期负载、性能、掉电恢复、社会涌现、完整渲染或独立用户收益。

运行时为 Python 3.12.10 和固定的 61 个 wheel，未还原上游历史完整依赖锁。官方 PyPI 超时后使用清华 TLS 镜像，版本和 SHA-256 保存在清单中；镜像哈希不是独立发布者签名。
