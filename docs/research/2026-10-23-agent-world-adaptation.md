# 单项目路线验证：agent-world 的最小闭环改造

## 改变了什么判断

在没有 Godot 图形硬约束的假设下，agent-world 从“存在明确缺陷的改造候选”推进到“隔离核心上的最小改造路径已执行通过”。当前可继续沿单项目路线验证实际代理与玩家操作，没有理由引入第二套世界状态系统。未证明它比 Microverse 改造更省工，也未完成用户想要的真实社会模拟游戏。

第一性原理：研究应该减少一个具体工程决定的不确定性。上一轮已经发现存档与行为读取缺口；继续读报告不会证明它们可补齐。因此本次只实现并验证能改变选型的最小适配，结果作为人工补充实测回到原需求，不改写历史模型判断。

## 上游和新增实现分开

基线为 `sbenodiz/agent-world@13d62dbdeeca07c7b5bb3b8aa264ca9834b01882`。原版 36 份文件运行前后核验 Git blob 不变，依赖沿用原实验的固定 wheels 与 SHA-256。Windows、Python 3.12.10、Django 4.2.26，SQLite 默认连接寿命 0。

只在新隔离副本修改 `world/agents.py`、`world/models.py`，新增一份迁移。批量保存不再在事务内关闭连接，保存异常向调用者传播；同一事务保存角色和世界检查点。新增 `adapter.py` 复用原版 tick、地图、动作、事件、关系和 ORM，补充时钟、随机状态、待消费事件、关系累计、共享资源与策略状态的保存恢复。载入时核对检查点哈希和角色行，拒绝静默拼接不一致状态。

Alice/Bob/Cara 的角色策略、供水事件、资源变更和记忆用途均为本次新写的确定性规则。它们不是原版 NPC 能力，也不证明 LLM 智能或社会涌现。改造内容和补丁完整归档为 `adaptation.json`，SHA-256 与实测记录绑定；上游提交只代表基线，不能显示成改造前后“同版本”。

## 真实观察

| 检查 | 观察 | 判断边界 |
| --- | --- | --- |
| 3 角色 / 30 tick | 90 条实际决策，经原版动作分发执行；时钟至第 1 天 13:30 | 规则原型，不是完整游戏 |
| 新进程恢复 | 13 tick 状态与新进程载入一致；再跑 17 tick 与连续 30 tick 的语义状态和轨迹一致 | 比较仅忽略事件时间戳；未测任意时刻崩溃 |
| 世界状态 | 角色、位置、关系、记忆、资源、随机状态、未消费事件及已有决策参与比较 | 非并发 Web/MCP 会话 |
| 单动作双方关系 | whisper 后无需等待定期刷新，新进程恢复双方各 +1 | 新适配器的动作事务，不是上游已修复 |
| 资源守恒 | 初始 12，累计供给 101、消费 86，剩余 27；无负库存、无未满足消耗 | 合成供水规则，没有真实经济或玩家验证 |
| 事件行动对照 | 其余状态相同，Bob 从 normal-use 改为 ration；屏蔽事件后两边都是 normal-use | 证明新规则读取事件 |
| 关系行动对照 | Alice 的关系 -80/+80 对应 withhold/coordinate；屏蔽关系后两边都是 coordinate | 不是自然关系演化的质量评估 |
| 记忆行动对照 | Cara 无/有阀门图记忆对应 inspect/repair；屏蔽记忆后两边都是 inspect | 不是 LLM 长期记忆效果评估 |
| 存档异常 | 角色写入后注入检查点异常、SQL trigger 在 Bob 行写入时拒绝，两种情况下异常均传播，角色及检查点回滚；新进程仍为旧状态 | 显式存档事务边界，不等于掉电或 OS kill 验证 |
| 损坏和混合资料 | 检查点文本损坏、角色行被单独修改时拒绝载入 | 不自动修复损坏存档 |

首次运行遇到 Windows 网络运行时初始化失败，曾调整 asyncio 导入顺序。后续出现子进程异常退出、父进程 heap corruption 和启动无响应；新增单动作断言后的运行也在损坏校验子进程以 3221226356 退出，无应用错误栈。失败记录和启动挂起进程身份均保留，根因未确认，不能宣称稳定性问题已解决。

最终驱动增加 45 秒启动栈诊断；子进程由驱动仅传入 SYSTEMROOT/WINDIR/TEMP/TMP，并断言环境白名单，保留这些系统变量，不再在导入后清空环境。2026-10-23T05:52:32.388667Z 完整运行成功：27 个独立子进程，含单动作双方关系、待消费事件和全部故障断言。此成功不证明环境调整是原生异常的根因修复。结果由 `latest.json` 指向 `execution-20261023T055130490691Z`；脚本记录 stdout/stderr 与退出码，不自动重试失败实验。

## 对抗式审查与下一步

新规则里写明“事件影响动作”，再运行得到差异，并不能证明候选原有智能；它只证明这一有限扩展可以经真实接口执行和恢复。输入屏蔽对照能排除部分无关变化，但不能评估生成式代理质量、玩家体验和长期稳定性。

完整服务的异步并发、速率限制下的真实代理循环、任意 tick 中途退出、旧数据库升级、Godot 图形和外部 LLM 均未验收。重启试验仅在完整步骤边界进行；上游周期性保存仍可能在步骤中写角色，不能据此承诺任意故障点的事务恢复。适配器目前拒绝无检查点的既有角色库，不能当作通用迁移方案。

下一步应围绕真实使用入口验证一个持续角色循环和观察/干预流程，先测试完整服务是否能承载该路径；只有外部代理行为与失败恢复可信后，才讨论完整游戏。若实际服务集成需要重做大部分核心，则重新比较路线。机会捕手继续负责选型与验证证据，不扩展成社会模拟游戏开发平台。
