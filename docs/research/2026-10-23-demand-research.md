## 需求与交付

用户希望从“如何实现多 agent 交互，例如社会模拟游戏”开始，由产品拆解需求、搜索 GitHub，优先寻找可直接采用或改造的实现，只为具体缺口考虑组合。助手按用户授权扮演使用者，通过真实 Edge 界面提交以下问题：

> 我想做一个社会模拟游戏。多个 AI 角色有自己的身份、记忆和目标，能自主交流、形成关系，并根据共同世界里的事件采取行动。玩家可以介入和观察。帮我找可复用的开源实现，优先考虑能直接运行的项目。

新增 `/research` 与独立需求任务 API，不沿用机会分析必须选择 2～3 个项目的约束。任务保存原问题、需求假设、真实检索、候选取舍、采集原文、能力覆盖、路径分工、剩余工程、实验和反方结论；支持历史、刷新恢复、编辑后重新研究及 JSON 导出。SQLite schema 14 保存任务和阶段快照，重启中断不自动重跑模型。

## 回源和对抗式复核

第一阶段评估把 Microverse 的所有必须能力判为资料支持，提出 adopt。逐字引用核验通过，只说明引用确实存在。

反方审查随后给出 reject，`capabilitiesGrounded=false`，最终没有推荐：自主任务不充分证明角色自己的长期目标；“复杂社会关系”没有具体状态与更新规则；环境感知不充分证明共同事件持续改变行为。界面保留原评估及其否决原因，避免重写历史以制造一致结论。

助手再次读取保存的 README，确认这些限定：原文明确写“本仓库开源的是《Microverse In Box》游戏在2025年6月的初版Demo”，不能将 Steam 完整版当作开源仓库能力。README 确有长期记忆、任务管理、环境感知、玩家对话及启动步骤，但这些仍是作者自述，不能证明行为闭环或实际可运行。关于 Ollama 与 API 密钥的描述也需要进一步核查。

Concordia 原文明确描述实体目标、记忆组件、engine 调度和 Game Master 结算，并提供 GUI/CLI 指南链接；它值得作为底层替代继续核查，不能因其是库就忽略已有界面线索。本轮没有继续读取该指南，也没有证明它满足完整玩家游戏体验。该方向仍有候选覆盖与语义判断风险，不能称为“全 GitHub 最优方案”。

后续固定提交源码核查已完成一轮：发现 Microverse 的状态读写与占位实现风险，也确认 agent-world 存在关系更新和事件分发的具体调用链，因而应将后者与 Microverse 并列验证，而非只验证首选。详见[源码对照](2026-10-23-social-simulation-source-audit.md)。下一步是有界运行实验，再决定改造还是补搜；没有依据先增加第二个组件。产品本轮仅输出实验步骤，没有安装或执行这些仓库代码，没有验证素材授权、接口兼容性、规模或运行成本。

## 演化判断

从第一性原理看，用户需要减少从目标到可验证实现路径的工作，单项目采用、改造、组合与证据不足均可推进决策。需求驱动入口提供明确完成标准，比单纯增加项目或组合数量更容易验证价值。

反面是：一次成功的谨慎拒绝并不证明流程已经好用。召回范围有界、README 可能夸大能力、评估与反方可能同时误判，长上下文和数分钟等待也可能抵消收益。本轮已真实暴露两次失败，下一步应优先补关键能力的可核查证据与任务完成对照，避免在闭环未证实前扩展通用自动开发平台。助手自用只能验证流程，尚无独立使用者省时或判断改善的证据。

## 证据抽取与路径综合拆分

对抗复核发现，原单次重评需要在同一 JSON 中同时生成多能力五步源码链、候选路径、能力覆盖、反方审查和实验，且必须给出逐行原文引证；真实任务出现不完整 JSON 和跨行引文。续研现拆为三阶段：选文件、只基于源码抽取并核验能力发现、仅基于已核验发现综合路径。发现先写入新任务快照；若综合失败，显式恢复只重复综合，不重复 GitHub 读取或证据抽取。原失败快照保持不变。

这是降低单次输出复杂度和重试浪费的工程假设，不是稳定性或效用证据。专项测试覆盖阶段输入隔离、引文核验、失败综合恢复及不重复采集；真实模型 canary 运行和与原单阶段的同任务成功率、耗时、token 对照仍待验证。任何方案仍须通过源码核验和反方硬检查，模型调用成功本身不代表用户价值。

针对相同失败源码的第一次恢复仍产生无效跨行引文。随后把模型引用格式收紧为单一 `line` 字段，服务端将其确定性映射为同一行范围；二能力评估仍输出不符合引用契约的范围并被拒绝。单能力 `shared_world_events` 另选 `world_state.py`、`event_resolution.py`、`step_controller.py` 三个文件，共 30,459 字符；评估输出不完整 JSON，复用已采源码再次调用后，本机 Codex 未完整结束。所有任务保留源码、提交、调用状态与失败原因；没有伪造研究结果或运行上游项目。

可证明的是完整目录与模型可见路径可分离，单次选文件可见路径限制为 160 条；不同输入范围的 token 观测不能证明同条件成本下降，也不能证明短名单召回无损或最终研究有用。对抗性结论是评估调用的输出完整性与逐字引文合规仍是首要阻塞；在失败快照上反复重评会增加调用，不构成价值。该阶段短名单、引用行映射和失败评估恢复的分析专项测试 21 项通过。独立用户收益和手工选型耗时基线仍缺失。
