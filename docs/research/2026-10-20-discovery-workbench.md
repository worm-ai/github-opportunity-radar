# 发现工作台：从项目列表到下一步判断

2026-10-20。产品仍以 [PRD](../PRD.md) 为锚点。本轮停止扩展地图案例，回到用户发现新能力、决定研究或停止的成本。

## 问题与取舍

原首页主要是英文仓库列表与零结果研究简报。旧六类能力规则偏 AI，Map Design、Frameweaver、GenOffice、Airbyte 等能力没有被充分呈现。首次收录时间已正确作为数据库主排序，但同批项目仍按旧存储分数排列，而接口会重新计算分数；改为名称稳定排序。

新发现视图从项目描述提取有原文依据的研究线索，展示创建与首次收录、最近两次观察、版本来源、下一步检查。默认先分散能力方向；用户可以筛选或选择组件，带入既有定向研究表单。它降低查找与准备步骤，不把标签当成可用性或商业质量评级。

原文抽查发现两个反例：

- `anywhere-labs/dsh-desktop` 的 README 视频生成词来自赞助广告，不能据此说桌面项目能生成视频。
- `kirklandsig/halo2-decompiled` 的 README 编程 Agent 词来自给贡献者的提示，不证明仓库提供 Agent 能力。

因此仅 README 命中全部进入待识别，保留逐字原文供核对。课程、教材和生活指南保留为资料线索。偏保守会漏掉能力，这是当前明确接受的代价；不能通过增加关键词把未知包装成确定判断。

观察库保留 94 条记录。真实数据中的若干 `null → tag` 来自此前未读到版本标签，不能称作新发布；本次没有确认两个已知标签之间的变化。原有发布可查看，关注度差值保留两次观察时间，不能外推为持续增长或新增能力。

## 验证和边界

- 100 项测试通过，包含批量观察查询、来源逐字摘录、描述优先、资料归类、广告反例、版本未知恢复与首次收录边界。
- 全仓类型检查、生产构建通过；随后改动的发现模块与存储测试再次通过。
- Edge 验证地图、Office、视频、数据同步四个方向的筛选与原文，核对所有返回线索确为已采集源的子串。
- 选择两个组件后，研究页面正确预填，研究问题仍待填写；没有自动提交。测试记录没有写请求，分析运行编号保持不变。
- 390px 页面可展开原文、选择组件，无水平溢出；六个移动导航入口均可见。
- 旧导航、24 个有 Issue 样本的项目、报告下载、实测图片/PPTX 下载继续通过，浏览器无页面错误。

末次移动导航样式构建后，复验发现旧生产进程尚未注册新哈希资源；按“构建完成 → 重启 → 浏览器验证”的顺序修正后，两套 Edge 检查均通过。README 已写明这一生产更新约束。

发现展示采用本地确定性线索，原文摘录仍可能包含夸张声明或广告。描述是项目作者自述，未执行核验。README 的档案观察时间不保证每次重新获取；技术分与模型机会分析未被更改。没有用户使用时长对照、访谈、试用或付费证据，不能称市场验证完成。

## 下一阶段

已让“查方向 → 看原文 → 选择组件 → 写研究问题”可直接操作。下一阶段应评估这些材料能否帮助用户提出具体工作假设，并处理待识别项目与非互补组合，而不是扩大某一案例或堆叠更多标签。验收应围绕真实任务与来源准确性，允许方向被停止。
