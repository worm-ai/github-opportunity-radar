# 持续关注：离开搜索结果后的真实仓库刷新

日期：2026-10-20；PRD 0.10 / DESIGN 0.14；数据库 schema 11，模型提示仍为 v4.3。

本轮先修复产品承诺的缺口：此前周期扫描只更新再次命中搜索的仓库。已收录项目离开结果后，研究者即使保存了“等待变化”判断，也没有独立刷新入口。持续监测不能只依赖搜索再次命中。

## 交付行为

项目档案新增独立“持续关注”开关和一次性“刷新仓库资料”。旧项目升级后不自动关注；保存研究判断也不会代替这个开关。首页显示关注项目的最近结果、变更摘要、失败与下次到期。

每工作区最多关注 20 个项目，每分钟检查到期项，每批串行处理两个；成功周期沿用设置，当前为 24 小时。每次实际经过 iii `collect-evidence`，调用 GitHub 官方接口，更新仓库元数据、README 摘录、Release 标签与有限近期 Issue，写入 World2Agent 信号及观察历史。指定讨论评论和补充文档仍需分别核查，不自动调用模型。

失败保留旧资料；部分失败显示警告并约一小时后重试。限流保留未来重试时间并暂停关注队列，取消后重新关注不能绕过。仓库数字 ID 发生变化时拒绝覆盖。服务重启保留开关、上次成功和失败信息，中断任务标记失败后延迟重试；关机时不执行。

## 隔离验收及发现的问题

- 157 项测试全部通过，包及 Server 编译、Web 类型检查和生产构建通过。
- `scripts/verify-monitoring.mjs` 使用真实 iii、临时 GitHub HTTP/SQLite 和 Edge，验证一次刷新不订阅、从未命中搜索的关注项目自动更新、取消后不复活、404 保留旧证据、重开持久化、桌面与手机界面。零生产写入、零真实 GitHub 请求、零模型调用。原始结果在 `.data/browser/monitoring-verification.json`。
- 实际浏览器发现 controlled checkbox 在请求期间回跳，已修正即时选择状态；刷新按钮同时识别正在运行的扫描。
- 真实 iii 暴露的跨进程错误与本地替身不同：SDK 通用错误丢失 GitHub 异常类型。适配器保留本进程实际 callback 的原始失败，使 404/429 状态和重试时间可传到路由；引擎失败不回退。新增传输错误回归测试，真实浏览器 404 验收通过。
- 详情接口的限流不能降为普通部分失败：按需仓库采集现在将详情中的 429 连同 retryAt 传回调度器；普通详情失败仍保留可用字段。
- 隔离 pipeline 再次通过原文引用、反方审查、定向研究、缓存、持久化、导出与密钥隐藏检查，使用本地模型 HTTP 替身。生产只读 Edge 导航、三个技术档案、下载与移动端回归通过，页面零错误。
